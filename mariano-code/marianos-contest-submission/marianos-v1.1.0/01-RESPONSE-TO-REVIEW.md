## 1. Retention – DONE (code + offline tests) · live evidence PENDING LIVE
* `src/mscraper/parse.py → map_product`: the `no_price` and `no_upc` rejections are removed.
  * no store price → the row is kept with `regular_price`, `sale_price`, `ppm` = `""`; `observations.json` records
    `availability: no_store_price` (test `test_product_without_store_price_is_kept_with_empty_price_fields`)
  * no UPC → the row is kept with `upc: ""`; identity `product:<Mariano's product id>`, stored as

  `item.upc` = the product key = `data.id`, and a top-level `prod.id` does not exist – the fallback could never fire

* Carried observations: `src/mscraper/retention.py`. A product of the last published dataset that a run does not return
  is output unchanged, with its own last `crawl_date`; `observations.json` marks `status: carried`, `last_observed`,
  `last_observed_run`, `carried_since`; fresh rows have `status: fresh`, `first_observed`. Carried indefinitely
  (tests `test_carry_forward_keeps_missing_products_with_their_own_dates`,
  `test_second_run_carries_products_it_did_not_see`).
* Validation measures price completeness only over priced rows and UPC completeness only over rows that carry a UPC,
  so kept unavailable products can never make a run fail or disappear.

## 2. Weight filtering – DONE (code + offline tests)
* `exclude_sold_by_weight` is removed from settings and code.
* `parse.approximate_weight_trigger` excludes only when Mariano's own displayed size or price wording is approximate /
  estimated. Real case: sold-by-weight steaks are displayed as `"about $10.39 each"` (item `weightPerUnit 0.8 lb`) –
  that wording excludes them; every exclusion is written to `exclusions.json` with the field and exact text.
* A product sold by weight with an exact displayed price is kept (test `test_sold_by_weight_alone_never_excludes`);
  titles such as "(About 3 Steaks per Pack)" do not trigger anything (`test_title_count_phrase_is_not_an_approximate_weight`);
  bulk / family-pack / multipack sizes are preserved exactly as displayed and are never treated as promotions
  (`test_family_pack_label_is_not_a_volume_deal`).
* Setting `crawl.approximate_weight_price_wording` (default true) controls whether price wording counts; size wording
  always counts.

## 4. Offers – volume terms DONE · digital association partly obtainable, dependency stated
* Volume: wording preserved + the terms of the same Mariano's object appended, e.g.
  `Save $1 each when you buy 5 or more (valid 2026-10-07T00:00:00Z to 2026-10-27T23:59:59Z; applies to: in-store)`;
  multi-buy prices `2 For $5.00 (valid until 2026-10-28T03:59:59Z)` with `volume_deals_price 5.00`. Every offer is also
  kept structured in `observations.json → offers` (kind, text, template, displayed price, valid_from, valid_to,
  modalities, limit, source path). No price is ever calculated; a family-pack label is never a promotion.
* Digital, obtainable now: Mariano's own search filter `savings=Coupons` (verified live 21 Oct: request variables
  `savings: ["Coupons"]`, products returned) identifies products that have a digital coupon. v1.1.0 runs one filtered
  request per shelf and records `digital_coupon_available` with the evidence response SHA-256 in observations.json.
  The `digital_deals_*` fields stay empty unless the terms are shown, so nothing is invented.
* Exact dependency for full product ↔ coupon terms: the coupon's qualifying products are loaded by the Mariano's web
  app after page load (the "Shop All Items" button opens a script-driven modal; anonymous visitors see "Sign In To
  Clip"). They are not in the server HTML. The current provider endpoint (Oxylabs Web Scraper API, Kroger) accepts no
  cookies, headers or page actions (verified: HTTP 400 UNSUPPORTED_BODY_PROPERTY) and does not serve product detail
  pages (/p/, HTTP 500 after its retries in 4 tests). Needed: a browser path that can click "Shop All Items" (a
  provider with page actions, or a self-hosted browser on a US proxy) and, for clip-required terms, a Mariano's
  customer account. The 24 coupons with full displayed wording, restrictions (e.g. "PICKUP OR DELIVERY ONLY") and
  expiry are already collected in coupons.json.
