What changed:
  1. A provider HTTP-200 body that is not JSON, or is JSON of an unsupported shape, now raises "malformed" with the
     original response attached. Before, it raised an unattributed exception (fetch.py:64). Provider 4xx/5xx bodies
     are attached as well (fetch.py:58).
  2. Every attempt where a response arrived but could not be used is preserved (fetch.py:193). This covers an
     unparseable envelope, a page that fails parsing, a page that is too small, and a non-refusal HTTP error. Empty
     bodies are recorded too. Retry and stop behaviour is unchanged.
  3. evidence/failed/ keeps:
       - original_sha256: the sha256 of the exact body received
       - a sanitized copy, cut to evidence.failed_response_max_bytes (1,000,000), with its own stored_sha256 and a
         "truncated" flag
       - a failure receipt: URL, sanitized request body, attempt, request sequence, budget name and budget ledger line,
         requested_at, failed_at, error kind and message, provider and target status, provider request id
     The receipt is also in receipts.jsonl and in the checkpoint "response_failed" event (evidence.py:162,
     runner.py:102). The probe command archives the same way.
  4. Credentials stay out. Request headers are never stored. Credential, cookie and session keys are redacted at any
     depth. Bearer and Basic values, URL passwords and the literal values of the configured credentials are removed
     from text (evidence.py:79-96).
