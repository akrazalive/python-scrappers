HOW IT WORKS (summary)
- Each request goes through the Oxylabs Web Scraper API (Kroger endpoint) with the store pinned. The scraper reads Mariano's own page state (store price, sale, PPM as displayed, UPC, offers, taxonomy). It does not rely on CSS selectors.
- Subcategories come from Mariano's site menu for each CSV department. Products are kept only when their taxonomy code belongs to the subcategory.
- Volume and digital deals are kept separate, with the retailer's wording. Prices are never calculated. Approximate-weight items ("about $X each") are excluded.
- Failed or blocked runs never replace good data. latest/ is written only after validation passes, and the previous dataset is kept for rollback.
- SQLite checkpoints let an interrupted run resume. This run was resumed once, live.
- Azure: a Container Apps Job runs Tuesday and Friday. It uses Blob Storage for output, Azure Files for checkpoints, Key Vault and Log Analytics. Deployment is one command (deploy/azure/deploy.sh).
- Estimated monthly cost: about $32-$115 per store. Details are in docs/COST.md.

HONEST NOTES
1. Scope of this run is a demonstration subset, not the full CSV. Mariano's server-rendered search returns only the first 24 results of a query, whatever page number is requested. Version 1.0.0 therefore covers each subcategory by query expansion: each new product's subcategory names and brand become further searches, up to a per-shelf cap. The attached run predates this, so Batteries and Light Bulbs show only the first 24 results (Mariano's reports 121 and 100), and 5 of the 28 CSV categories are represented. The scraper's own validation flagged this run as "demo scope (category subset / per-category limit): never published to latest/". That warning is accurate: this is a qualifying demonstration run (>=500 records, multiple categories, one assigned location), not the full production run. A second run with query expansion collected 950 records in its first wave, then stopped when my Oxylabs trial quota ran out. It is checkpointed and will resume when the quota is renewed.
2. Digital coupons: for an anonymous visitor, Mariano's shows coupon terms on the Coupons page, not in each product's data. The scraper captures every displayed coupon and fills digital_deals_* wherever Mariano's links the deal to a product. Signing in with a Mariano's account could link coupons to products; this is optional and can be discussed.
3. The run was re-validated with the final v1.0.0 rules. The records file is byte-identical to the collected one. The only change is that three Coffee menu links with no products of their own code at this store (Creamers, Filters, Espresso Machines) are now warnings instead of errors.
